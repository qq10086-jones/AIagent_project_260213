## 2. 本轮已完成工作 (What We Did)

### A. 模型主导权切换 (Model Pipeline Promotion)
- **动作**: 根据前期的 Learning M1 评估结果，将 `config.yaml` 和 `run_pipeline.py` 的主执行模型从表现较弱的 `ridge` 切换为最优的 **`shadow_ic`**，同时保留 `ridge` 和 `shadow_eq` 作为对照组平行运行（Compare Modes）。
- **结果**: 流水线端到端跑通。`shadow_ic` 验证回测展现了更高的最终净值（1.30M JPY，+30.07% 收益）和更稳健的回撤控制（-12.58%），正式确立为生产主模型。

### B. 实盘自动化与容错提升 (Operational Automation)
- **动作**: 修复了 `make_decision.py` 中关于组合最大回撤降仓逻辑的痛点。原先需要每日人工传入 `--peak_nav`，现已改为自动从 SQLite 数据库的 `account_snapshots` 表中查询历史最高净值（Peak NAV）。
- **结果**: 显著降低了运营的人工干预需求和实盘输入错误（Fat-finger）的风险。

### C. 评估体系闭环 (Evaluation Completeness)
- **动作**: 修复了此前在 `compute_ic.py` 中因缺失 `volume` 数据导致 `vol_z`（成交量确认信号）因子在 IC 评估中全为 0 的 Bug。
- **结果**: 目前全部 15 个 Alpha 因子均已实现真实交易宇宙（Screened Universe）下的 IC 计算与学习权重更新。

### D. News Worker 架构审视与重构设计 (News System Redesign)
- **动作**: 针对此前 Intern 版本的 News Worker 进行了深度的 Quant/PM 架构审视。指出了其存在未来函数（Look-ahead Bias）、无持久化、同步阻塞等重大缺陷。
- **产出**: 在 `design/` 目录下输出了三份生产级的治理和重构文档：
  - `NEWS_SYSTEM_DESIGN_v1.md`: 将系统转为异步入库、只读查询的架构，并引入了批处理流控（Token Bucket）。
  - `NEWS_SYSTEM_TASKS_v1.md`: 梳理了 P0 - P3 的落地重构计划。
  - `NEWS_GOVERNANCE_v1.md`: 制定了包括严格 PIT 过滤（`order_time`）、动态降级阈值（P5分布）、事件去重（TF-IDF）和模型质量基线（Golden Set）在内的治理规范。
- **实施**: 已完成 P0 的第一步，在 `trade_schema.py` 和 `db_update.py` 中正式引入了 `news_feed`、`news_sentiment` 等相关表结构与索引。

## 3. 当前架构状态评估 (Architecture State)

目前 `worker-quant` 作为一个**单体量化管线**，其本地内聚度极高，闭环能力完整。
数据更新 (`db_update`) -> 选股过滤 (`screener`) -> Alpha打分与回测 (`ss7`) -> 订单打包与风控 (`make_decision`) -> 因子效果自我学习 (`compute_ic`) 已经可以完全跑通。

但作为 Nexus 系统的一个 **Worker** 节点，其工程解耦和接口契约仍未完全达标，尤其是 News 模块仍处于严重的耦合状态。

## 4. 遗留问题与下一步 (Next Steps)

### Immediate (P0): 剥离新闻入库逻辑 (News Ingestion Decoupling)
当前 `worker.py` 体积过大且混杂了大量的网络爬虫逻辑，严重影响量化侧的稳定性。
- **任务**: 从 `worker.py` 中剥离底层的新闻抓取逻辑（如 `_fetch_news_from_google_rss`），建立独立的 `news_ingester.py`。
- **目标**: 将抓取到的数据写入刚建好的 `news_feed` 数据库表中，并基于 `raw_hash` 实现精准去重，彻底废弃原有的 `news.csv` 中间文件传递模式。

### High (P1): 实施打分引擎与流控 (Sentiment Engine & Flow Control)
- **任务**: 建立 `news_analyzer.py`，实现基于 LLM 的批处理异步打分机制。
- **目标**: 包含 Token 令牌桶限流、持仓股票优先打分、以及基于 TF-IDF 的同事件去重（`event_cluster_id`），保证不耗尽 API Quota 的同时消除新闻信号的"重读放大"效应。

### Next Phase (P0-N): 适配 Nexus Orchestrator 接口
*注意：等待主系统框架（Orchestrator）修改稳定后执行。*
- **任务**: 将上述 `make_decision.py` 生成的 `decision_snapshot.json`（含 `orders_proposal` 和降级风控状态）打包对齐到 Nexus 的标准 `quant_execution` 契约中。
- **目标**: 实现系统调度层对 Quant 单体的安全接管与执行降级监控。
