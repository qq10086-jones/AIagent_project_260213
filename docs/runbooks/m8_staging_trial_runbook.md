## Step 1 — Start Dev System (sequential mode, verify baseline)

```bat
cd infra
docker-compose up -d
```

Verify:
```
curl http://localhost:3000/health    →  {"ok": true}
```

This is your **baseline**. All workflows run sequentially. No parallel execution yet.

---

## Step 2 — Start Staging System (parallel + dynamic routing enabled)

In a **separate terminal** (keep dev system running on port 3000 for comparison):

```bat
cd infra
docker-compose -f docker-compose.yml -f docker-compose.staging.yml up -d
```

What this starts:
- `nexus-orchestrator-staging` on port **3001** (not 3000)
- Separate DB: `nexus_staging` (isolated from dev data)
- `staging_parallel_rollout.json` mounted: `master_enabled=true`, `dynamic_routing_enabled=true`
- `m7_exposure_cohorts_staging.json` mounted: `cohort_enabled=true` (fe_led only)

Verify staging is up:
```
curl http://localhost:3001/health    →  {"ok": true}
```

## Step 3 — Run Live Dynamic Routing Trial (WS-34-02)

```bat
cd orchestrator
node scripts/run_m7_dynamic_routing_trial.js ^
  --out artifacts/m8_trial/live_trial_result.json
```

Expected output:
- `mode: "live_trial"` (prerequisites met in staging)
- No fatal errors
- `artifacts/m8_trial/live_trial_result.json` produced

If mode is still `dry_run_preflight`, check staging orchestrator env:
```
docker exec nexus-orchestrator-staging env | grep -E "master_enabled|PGDATABASE"
```

## Step 6 — Tear Down Staging

```bat
cd infra
docker-compose -f docker-compose.yml -f docker-compose.staging.yml down
```

Dev system on port 3000 is unaffected. `nexus_staging` DB data is preserved in `pgdata` volume.

---

## Rollback

If staging trial shows problems:
1. Stop staging: `docker-compose -f docker-compose.yml -f docker-compose.staging.yml down`
2. Staging configs (`staging_parallel_rollout.json`, `m7_exposure_cohorts_staging.json`) do NOT affect dev or production
3. `production_parallel_rollout.json` remains `master_enabled: false` — production unchanged
