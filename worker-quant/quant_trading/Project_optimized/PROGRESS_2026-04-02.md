# Quant Project Progress — 2026-04-02

## PM / Quant Update (Late 2026-04-02)

### V2 分析链路的全面重构与上线 (Daily Analysis Pipeline Rebuild)

本项目在今天迎来了一次架构级的重大升级，从一个纯粹的研究型量化骨架，正式进化为了具备实盘“数据清洗 + 策略归因”双链路的**准机构级系统**。

核心解决的痛点是：此前系统的每日运行报告结构散乱、信号缺乏解释、无法处理大盘极端行情、且依赖了昂贵的收费 API。

#### 1. 动态因子更新链路 (Category A: Factor Refresh Pipeline)
我们彻底重构了盘后的数据“备弹”流程，使其完全实现了自动化且**零付费阻碍**。

- **数据源混合方案 (P0 实现)**：剔除了要求高昂订阅费的旧 J-Quants 依赖。创新性地引入了“混合架构”：使用完全免费的 `yfinance` 抓取无延迟的量价及技术指标；利用免费版的 `jquantsapi.ClientV2` 抓取高质量的日本股票季报（营业利润、净现金流等）。加入了 12.5 秒的速率限制以保障免费策略的稳定运行。
- **情报去噪**：剔除了噪音极大的泛世界新闻源，现在专注抓取 `BOJ（日银政策）`、`Trade（贸易摩擦）` 和行业特定新闻，极大地提升了新闻门控（News Gating）的情报信噪比。
- **IC 权重降频防过拟合**：将因子信息系数（IC）权重的更新频率从每日强制降级为每周一盘后，并增加了 `paper_days >= 30` 的锁定期保护，彻底锁死了过拟合（Signal Drift）的风险。

#### 2. 股票与策略分析链路 (Category B: Strategy Analysis Pipeline)
在开盘前或盘中执行的分析报告生成器（`quant_briefing.py`）被重写为 V2 版本，加入了极具实战价值的**风险规避机制**。

- **大盘状态感知 (Regime Detection)**：首次引入自上而下（Top-down）的视角。通过监控日经ETF（1321.T）的近期真实日内振幅（5日 ATR/Close）与过去 60 日均值的偏离度（>1.5倍即判定为高波动），系统能够在发生大跌前拉响“全面防御”警报，阻止任何新仓位的买入。
- **动态健康度与持仓止损 (Position Health)**：将固定止损升级为基于 ATR 的动态止损。根据个股波动率，自动计算 `max(ATR×6.0, 6%)` 的止损边界。当击穿止损线时，将在简报头部以 ⚠️ 红色警告强制置顶。
- **新闻与量化信号的交叉验证 (Cross-Validation)**：在模型给出的买入信号最终确认前，系统会调用昨天抓取的精确新闻进行对撞。如果公司有财报暴雷，或行业遭遇类似“关税制裁”的宏观系统性风险，将直接在信号旁打上 🟡 / 🔴 风险标签，避免盲目接飞刀。

#### 3. 样本外回测验证 (Walk-forward Validation)
为验证新架构在真实实盘中的鲁棒性，我们在 2025年4月1日 到 2025年10月1日 期间进行了严格的盲测（Out-of-sample Walk-forward Test）：
- 面对冷启动，系统极度克制，耐心地等待了长达一个半月的特征“预热”（直到 252 天数据达标），在没有确切把握前一笔不买。
- 最终，当前的主力生产模型 `ridge` 贡献了 **+8.03%** 的纯利，并将最大回撤死死压制在极其优秀的 **-2.86%**。
- 后台影子运行的新型复合模型 `shadow_ic` 更是拿下了 **+13.86%** 的惊艳收益（最大回撤仅 -2.46%），完美印证了“影子赛马”晋升机制的正确性。

### 结论
目前 V2 版本的双链路（数据清洗 A 链路 + 报告生成 B 链路）已经部署完毕，并经过了历史极端行情的交叉验证。系统不仅知攻（选出好股），更知守（在今天日经暴跌 -2.58% 时成功触发观望防守）。

**下一步**：系统已进入“静默运转期”，建议通过 Windows 任务计划程序挂载 `daily_run.bat`，开始正式的每日自动化观察，为接下来的实盘发单做最终准备。

The main open issues are now more concrete:

1. Zero exposure persists too long.

2. Signal-mode switching is not currently a real fix.
   All compared modes (`ridge`, `shadow_eq`, `shadow_ic`, `shadow_hybrid_ic`) currently export zero latest weights, so "switch to shadow_ic" is not yet supported by live evidence.

3. Factor quality is too narrow.
   The current production-eligible factor set is effectively one-factor (`mom_consist`). The rest of the technical factors are currently better treated as cleanup candidates than trusted production contributors.
