### 2.2 acceptance.json Schema 升级 (QA-05 → QA-01 的根基)

**文件**: `contracts/coding_team_pm_acceptance.schema.json`

```jsonc
// 现在: criteria 是 string[]
{
  "criteria": {
    "type": "array",
    "items": { "type": "string", "minLength": 1 }
  }
}

// 改为: criteria 是 object[]，每条带可执行验证
{
  "criteria": {
    "type": "array",
    "minItems": 1,
    "items": {
      "type": "object",
      "required": ["id", "description"],
      "properties": {
        "id":               { "type": "string", "minLength": 1 },
        "description":      { "type": "string", "minLength": 1 },
        "verify_command":   { "type": "string" },
        "expected_pattern": { "type": "string" },
        "verify_tier":      { "type": "string", "enum": ["deterministic", "semantic", "manual"] }
      }
    }
  }
}
```

- `verify_command`: 可执行的验证命令 (走 verification_runner 的安全白名单)
- `expected_pattern`: 预期输出的正则匹配
- `verify_tier`: 该条标准的验证类型 (默认 `deterministic`，无命令时降级为 `semantic`)
- **向后兼容**: PM 步骤如果只输出 string，validator 自动包装为 `{ id: "AC-N", description: str, verify_tier: "semantic" }`

### 2.3 Smoke Test → Acceptance Test 扩展 (QA-02)

**文件**: `orchestrator/scripts/run_smoke_test.mjs` → 新增 `run_acceptance_test.mjs`

```
执行流程:
1. 读取 plan/acceptance.json
2. 过滤 verify_tier === "deterministic" 且 verify_command 非空的条目
3. 启动 server (复用 smoke 逻辑)
4. 逐条执行 verify_command，比对 expected_pattern
5. 输出 acceptance_result.json (per-criterion pass/fail + evidence)
6. 综合 verdict: 全部 deterministic pass → "pass"，否则 "fail"
```

**smoke_test 步骤改造**: 
- 先执行原有 smoke (L1: install + start + root probe)
- 再执行 acceptance test (L2: per-criterion verification)
- 两层都 pass 才算步骤通过

### 2.4 QA Report 加固 (QA-01, QA-03, QA-04)

**Schema 变更** (`coding_team_qa_report.schema.json`):

| 字段 | 现状 | 改为 |
|------|------|------|
| `journey_checks` | optional | **required, minItems: 1** |
| `rubric_citations` | optional | **required, minItems: 1** |
| `acceptance_test_results` | 不存在 | **新增 required**: 引用 acceptance_result.json |

**qa_verify 步骤 prompt 改造**:
- 注入 acceptance_result.json 的确定性结果
- LLM 的语义审查补充确定性测试未覆盖的条目
- 禁止 LLM 覆写确定性测试已 fail 的条目 (确定性 > 语义)

**验证链改造** (`artifact_pack_validator.js`):
- 现有: `verified_artifacts ⊇ acceptance_ids` → 形式检查
- 新增: `acceptance_test_results` 中所有 `deterministic` 条目必须 `status === "pass"`

| 风险 | 影响 | 缓解 |
|------|------|------|
| MiniMax M2.7 生成的 acceptance.json 格式不稳定 | PM 步骤输出不符合新 schema | 向后兼容包装 (1.2) + prompt 强化 |
