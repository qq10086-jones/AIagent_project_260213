## Open questions for Step 2 design

1. **Type contract vs runtime check?** We can make `asof` a required kwarg everywhere, or build a `PITConnection` wrapper that rewrites queries. Wrapper is harder to reason about; explicit kwargs surface the bug at call sites.
2. **Live data refresh path** (`market_data_utils.latest_db_date`) legitimately needs system clock — propose marking functions with a decorator `@live_only` so test harness can detect accidental usage in backtest.
3. **`fundamental_snapshots.available_ts` vs `report_date`** — audit confirms `screener.py` uses the correct column. Need to sweep any remaining `report_date` usages (not counted above; separate D-6 task).
4. **feature_daily regeneration** — after fixing `compute_price_features.py:127`, existing `feature_daily` rows are contaminated. Plan a one-shot rebuild + snapshot.

## Methodology note

Audit is static (grep + function-boundary inspection). A PIT_SAFE label means the query site itself is bounded; it does NOT prove every caller passes a correct asof. Step 2 will add runtime tests: given `asof=T`, replace data where `date > T` with NaN; assert outputs identical.
