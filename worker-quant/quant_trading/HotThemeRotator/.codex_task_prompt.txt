## 18 Review Questions

### Implementation Correctness

1. **Yanoshin parser unwrap robustness**: parser does `inner = raw.get("Tdnet") if "Tdnet" in raw else raw; if not isinstance(inner, Mapping): continue`. Robust against `{"Tdnet": null}` / `{"Tdnet": "string"}`? Robust against deeply nested `{"Tdnet": {"Tdnet": {...}}}`?

2. **`_normalize_pubdate` ambiguity**: handles `T-separated → passthrough`, `space-separated → add T + JST`. But what about `T-separated WITHOUT TZ` like `"2026-05-25T18:15:00"`? Currently passthrough — no TZ enforced. Per Rule 8.2 PIT, should naive timestamps be rejected? Or assumed JST?

3. **disclosure_id 64-bit collision risk**: SHA-256 first 16 hex chars = 64 bits. Birthday paradox: collision expected around 2^32 ≈ 4 billion records. For HTR scale (≤1000 disclosures/day, ~10 years horizon = 3.65M records) is 64-bit sufficient, or should it be 32 hex chars / 128 bits?

4. **`YanoshinTdnetAdapter` rate limit bug**: rate limit state is per-instance (`self._last_request_ts`). If user runs `poll_tdnet_rss.py` from TWO Windows Task Scheduler instances concurrently, each has own adapter → each respects own 5s independently → total 2x rate. Process-wide token-bucket file would fix. Acceptable for single-user, or should fix now?

5. **`PriceOrchestrator._consensus_check` failure semantics**: when high_salience=True, primary succeeds but ALL consensus sources raise — currently returns primary unflagged. Should it instead mark `fail_reason="consensus check unavailable"`?

6. **`PriceOrchestrator._cache_lookup` O(N)**: iterates all entries per lookup. Fine for ≤120 entries (single user, ≤20 tickers × 6 sources). Premature optimization risk noted, but worth tracking?

7. **`JquantsLiveBridge` token TTL bug**: idToken cached in-memory without TTL tracking. After 24h instance reuse, fetch returns 401, no auto-refresh. Cycle 1 acceptable or fix now?
