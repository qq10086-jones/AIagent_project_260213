# Quant Project Progress — 2026-03-10

## PM / Quant Update (Late 2026-03-10)

### What Changed After Initial Handoff

The most important progress after the original handoff is not "more features", but "better truthfulness of evaluation".

- `screening_history` is now persisted, so Learning no longer evaluates a different universe from the one actually traded.
- `compute_ic.py` now evaluates the screened universe instead of the full price DB by default.
- `ss7_sqlite_news_overlay.py` now logs production-time `factor_signals` directly during signal generation.
- A production diagnostics script was added to measure IC on actual logged signals instead of only recomputed research signals.
- `ss7` now supports parallel signal-mode comparison: `ridge`, `shadow_eq`, `shadow_ic`.

### Current Product Truth

The project is operationally much stronger than before, but the current default production signal (`ridge`) is no longer the best candidate.

### Updated Interpretation

The project has crossed an important boundary:

- Before: good architecture, but uncertain whether the evaluation itself was trustworthy.
- Now: evaluation is much more trustworthy, and it tells us clearly that the current Ridge composite should not remain the unquestioned default.

### PM Judgment

The project should not be pitched internally as "ready for beginner real-money deployment".

It should be positioned as:

- research-capable
- operator-usable
- one iteration away from paper-trading readiness

That is a strong state for the project, but it is not the same thing as retail-ready automation.

### Nexus PM Judgment

From the whole-Nexus point of view, quant is now partially compliant but not fully compliant.

What is already good:

- real domain capability exists
- local execution chain exists
- learning and evidence tables exist
- risk-aware design exists

What still blocks full compliance:

- artifact contract is not fully normalized to Nexus requirements
- worker responsibility boundary is not yet explicit enough in the old design text
- approval / degradation / fallback behavior still needs clearer contract language

This means the right next step is not "more model complexity", but "better worker contract clarity plus safer operator flow".

### Alpha 因子升级：10 → 15 个因子

新增 5 个学术依据因子（全部可从现有价格/成交量数据计算）：

| 新因子 | 计算方式 | 学术依据 |
|--------|---------|---------|
| `mom_12_1` | `pct_change(252) - pct_change(21)` | Jegadeesh & Titman (1993)，规避短期反转 |
| `high52w` | `close / rolling_max(252) - 1` | George & Hwang (2004)，锚定效应溢价 |
| `vol_adj_mom20` | `ret20 / vol20` | Sharpe 比率类动量，波动率归一化 |
| `mom_consist` | `(ret1 > 0).rolling(63).mean()` | 持续上涨天数比例，过滤噪音动量 |
| `vol_z` | `log_volume z-score (60d)` | Blume et al. (1994)，成交量确认信号 |

**关键工程修复**：`mom_12_1` 和 `high52w` 需要252天历史，新增 `feature_burnin=252` 参数，
保证训练窗口完全覆盖有效数据区间（`start_i = train_window + H + feature_burnin = 524`）。

### Learning M1 实现

**新增数据库表**（`trade_schema.py` → `ensure_learning_tables()`）：

```sql
factor_signals    -- 每日每因子每股票的 z-score（47,967 行已写入）
factor_registry   -- EWMA IC 权重（各因子的学习权重）
risk_rules        -- 编码化风险规则（静态）
learning_audit    -- 不可变学习审计日志
```

**IC 计算引擎**（`compute_ic.py`）：
- Spearman IC = rank correlation（预测值 vs H期实际收益）
- EWMA 权重更新：`alpha = 1 - exp(-ln2 / 60)`，半衰期60个交易日
- 门控阈值：t-stat = `|IC_mean| / (IC_std / √n) ≥ 1.5` 才更新 `factor_registry`
- Shadow 模式：`--shadow` 只计算不更新权重（纸上实盘等价）

### IC 分析（最近60个调仓期，H=20）

| 因子 | IC均值 | ICIR | t-stat | 门控结果 |
|------|--------|------|--------|---------|
| `vol_adj_mom20` | +0.0331 | +0.205 | 1.45 | FAIL（差一点）|
| `rsi14` | +0.0269 | +0.176 | 1.25 | FAIL |
| `high52w` | +0.0285 | +0.138 | 0.94 | FAIL |
