### 4.3 断裂的机制诊断

1. **advice 的物理形态是磁盘 JSON + 需要主动打开的仪表盘**;notifier 仅有骨架
   (`api/notifier.py` toggle API,desktop/email/telegram 三通道全关,Rule 12.7 双确认从未执行)。
   flag 触发日与 owner 知晓日之间没有任何推送。
2. **advice 不是 first-class 对象**:没有 ID、没有状态机(open/executed/declined/expired)、
   没有年龄。"决定不执行"与"没看到/没来得及"在系统里不可区分,也就无法测量、无法改进。
3. **B sleeve 预承诺在空转**:`verdict_date 2026-08-26, on_fail: unwind_to_A` 挂在
   **从未建立的仓位**上——8-26 将产生一个关于不存在持仓的判决。预承诺机制的可信度依赖
   "承诺的事会发生",空转一次,下一次承诺的约束力就打折。

### 4.4 更大的泄漏:带外欠配这个"第三种状态"(2026-08-06 补)

§4.2 那笔是**一次性**的。持续中的那笔在这里。

08-05 快照(`OBSERVED`):NAV ¥387,881,β 调整敞口 ¥247,411,比率 0.638x,`below_band`。
但该快照**仍把已卖出的 8035.T 计为持仓**(§14 journal 末条仍是 07-14 的 1568 tranche 1),
所以 0.638x 本身就是失真读数。

剔除 8035 后(`DERIVED`,临时价口径同 §4.2):

| 项 | 值 |
|---|---:|
| β 调整敞口 | ¥247,411 − 58,550×1.5 = **¥159,586** |
| 临时 NAV | ¥387,881 − 3,560 = **¥384,321** |
| 敞口比率 | **0.415x** |
| 距声明带下沿 1.2x | 1.2×384,321 − 159,586 = **¥301,599** |

`0.055 × ¥301,599 ≈ ¥16,588/年`——这是 **mandate 自身股权溢价假设下的模型隐含毛机会成本**
(`DERIVED`),**不是已实现亏损**。它不含 LETF 损耗、费用、择时、参数不确定性,也不假定
mandate 本身正确。它的用途只有一个:**说明这个长期未决状态的量级可能大于 §4.2 那笔一次性损耗**,
因此需要一个显式的 owner 决定,而不是继续沉默。

本文 §5 负清单已写"带是声明的,要么执行、要么走 Rule 4 改声明,不允许第三种状态"——
而账户自 07-13 授权以来**一直处在第三种状态**。P28 要求在一份带日期的记录里三选一:
① 按现有执行规则向带内部署;② 提 Rule 4 修改目标/带(记旧值、新值、理由、预期影响、验证);
③ 批准一个**有到期日**的限时例外。沉默或无限期例外不是第四个选项。系统 advice-only,
不能替 owner 选,也不能替 owner 执行(Rule 3)。

## 5. 建议(按优先级;每项含验收标准;采纳走 Rule 4)

### P1 — 修执行回路(最高杠杆,与 edge 无关)

  risk_mandate 面板渲染"券商侧已挂/未挂";未挂的整股仓位产生低噪声提示行。

**P1b 决策队列 first-class 化(建议立项 P28)。** 每条 advice 生成带 ID 的队列条目:
状态 open/executed/declined/expired、提出日、年龄(sessions)、来源规则。daily routine 每日打印

  8035 类事件的"触发→终态"延迟成为可查询指标。

**P1c 打开一个推送通道。** desktop toast 成本最低(notifier 骨架已在,按 Rule 12.7 双确认开启)。
只推**flag 状态转变**(armed→triggered、sunset 到期、kill-switch buffer 档位变化),不推日常。
- 验收:flag 转变日与推送日同日;月度推送条数有上限(防通知疲劳,Section 12 精神)。

### P2 — 换系统 KPI

NAV vs 大盘是 **owner 的成绩单**;系统的成绩单应为:
1. advice→action 延迟中位数(sessions);2. 规则遵守率(带内天数占比、括号执行合规率);
3. forward log 积累进度(vs 8-26 / Q4 里程碑)。
- 验收:三个数进入 afterclose 输出与 risk_mandate 面板。

### P3 — 冻结新信号研究至 8-26

### P4 — 治理减重(规则 sunset)

由 owner 决定保留/合并/废止。防止规则只增不减。

**如果觉得"没用",为什么?** 因为相当一部分亏损泄漏在一个与聪明才智无关的地方:回路三的

"发现"而不只是"否定";(2) P1 采纳与否——决定既有规则资产是继续折旧还是开始复利。
