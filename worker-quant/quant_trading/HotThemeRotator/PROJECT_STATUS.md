## Open Risks

**数据 / 服务层 (近期暴露)**

- **Stooq 服务政策 2026-05-25 变更** — 免费 CSV 下载现需 captcha 申请 apikey；P10-19 active chain 已剪除，但显示外部服务条款可单方面变更，是 scraping fallback 的结构性风险。
- **active price chain 仅 3 源** (yahoo_japan / kabutan / yfinance)，且前两个是 HTML scrape。HTML 结构改动 → parser 立即坏。Cycle 2 必须加 daily health check (Codex 推荐 — `health_check()` 每日跑 + endpoint status + parse 成功 + freshness 记录)。
- **Yahoo JP + Kabutan consensus 不是真独立验证** (Codex 警告)：两源很可能反映同一上游 JPX 数据，consensus check 主要是 parser failure detector，不是 feed truth verification。Rule 12.3 chase filter 决策时这个限制必须传达给用户。
- **TwelveData + J-Quants 用户无账号** (永久约束 2026-05-25)：高 salience 时无真正"独立 API 仲裁者"。inactive 代码保留为未来 optionality。
- **反思系统数据源 stale 风险** (Codex 警告)：无 J-Quants → Policy Replay 只能用 `Project_optimized/japan_market.db.daily_prices` (已 4-6 周 stale)。P11-03 acceptance 加 "data freshness gate" 拒绝 stale > N trading days 运行。
- **`Project_optimized/selected_tickers.json` asof = 2026-04-27 / `factor_signals` asof = 2026-04-13**：dashboard 与 morning_briefing `--source db` 实质是 4-6 周前数据。必须用 `--source yfinance` 或刷新 Project_optimized 才能用候选做今日判断。

**策略 / 校准层**

- **策略高胜率验证缺口**：需用盈亏比、尾部亏损、最大回撤、换仓成本验证，不能只看命中率。
- **A股 / 美股跨市场温度**：不能直接等价为可交易信号，仍作为风控 + 主题背景。
- **Backdated calibration 历史回填**：ADR-0006 + Rule 8.2.1 已加严格守护，但操作员必须用连续历史窗口（非 cherry-pick）+ git-pinned scanner config hash + 写 bootstrap_provenance.json — 这些自动化由 P10-13 实施。

**实施 / 工程层 (Codex 评审 2026-05-25 提出)**

- **Codex 评审 "not yet decision-grade for high-salience intraday alerts"**：W1 实施过了 mock-HTTP 测试 + live smoke 部分 endpoint 通过，但还没在真实生产环境下连续跑过一天。任何 Rule 12.3 chase 决策现在仍需用户人工最终确认。
- **YanoshinTdnetAdapter rate limit 并发 bug**：per-instance state 不防多个 Task Scheduler 实例并发。Cycle 2 解决方案：Windows Task `/Z` flag 禁止重叠运行（用户态 mitigation），文件锁留作 Cycle 2 之后。
